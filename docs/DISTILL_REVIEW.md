# Дистилляция «дерево → MLP»: насколько студент дотягивает до учителя

Дата: 19.11.2026. Ветка `refactor`. Код не менялся. Источники: код и пилот `results/pilot_ext` (1 сид, n_train=400 у adult/housing/covertype, 822 у wine), плюс короткий эксперимент (раздел 4).

## 1. Как устроена дистилляция (по коду)

| | Учитель | Студент |
|---|---|---|
| Модель | LightGBM / CatBoost (`DISTILL_TEACHERS`), параметры из `config/model_params/<ds>.json` с ограничениями `TREE_CAPS` (`study/protocol.py:28`), n_jobs=1 | `SimpleNN(input_size, output_size=K)` **с дефолтными слоями `[32, 16, 8]`, dropout 0.2** (`models/torch_models.py:390-405`, `DEFAULT_PYTORCH_PARAMS['simple']`). Датасетный конфиг MLP (`layers`, `dropout`, `learning_rate`) **не используется** |
| Параметры | — | adult 3.4k (85→32→16→8→1), covertype 2.5k (54→…→7), housing ~1.1k, wine ~1.0k. Для сравнения MLP основного исследования: adult [64,32,16] 8.1k, covertype [128,64] **15.8k**, housing [32,16,8], wine [16,8] |
| Обучение | на train (`fit(X_train, y_train, X_val=val)`) | на **тех же X_train** (n_train точек), цели = выходы учителя на X_train; без аугментации / дополнительных точек |
| Оптимизатор | — | Adam, lr = 1e-3 (`DEFAULT_PYTORCH_PARAMS['simple']['learning_rate']`), без weight decay и scheduler (у основной MLP: AdamW wd 1e-4 + ReduceLROnPlateau; covertype lr 2e-3) |
| Эпохи / батч | — | до `distillation_epochs=500` (`DISTILLATION_CONFIG`), mini-batch 128 (B11), early stopping по **loss на val к выходам учителя** (fidelity, не по метке), patience 30, восстановление лучшего состояния |
| Цели и loss | — | бинарная: `BCEWithLogits(logit, p_teacher)` — мягкие вероятности, температура **не применяется**; мультикласс: `KL(softmax(log p_T / T) ‖ softmax(z/T))·T²`, T = 2 (D2: при инференсе T=1 студент воспроизводит p_teacher); регрессия: `MSE(ŷ, ŷ_teacher)` в стандартизованной шкале y |
| Валидация | val split (100 точек в пилоте) | тот же val, но только как «насколько похож на учителя» |
| Что сохраняется | `teacher_metric` (holdout), `fidelity` (holdout: доля совпадения меток для классификации / Pearson r для регрессии), `baseline` = метрика студента на holdout | — Эпоха остановки, train-fidelity, val-loss **не сохраняются** |

Метрики: adult F1 (binary), covertype accuracy, housing/wine MAE (меньше = лучше).

**Вывод по таблице.** Студент воспроизводит учителя на 83–94 % меток (r 0.84–0.98 в регрессии) и в 5 из 8 случаев **не хуже или лучше учителя** (сглаживание 10 % шумных меток). Заметных провалов нет: худший случай — housing/CatBoost (+5.9 % MAE). Отставание дистилляции от «MLP на метках» на adult (0.55 против 0.63 F1) — свойство **учителя**, а не студента (см. 3.3).

## 3. Диагностика

### 3.1 Обучение (эпохи / lr) — **не узкое место**
Повторил дистилляцию пилота (те же числа: adult 0.5505 / 0.890, covertype 0.6810 / 0.865, housing 51 704 / 0.839, wine 0.5053 / 0.863). Early stopping срабатывает на **150–240-й эпохе из 500** (лучшая эпоха 159–214), т.е. лимит эпох не упирается, val-loss к учителю вышел на плато. lr=1e-3 с Adam для сети ~3k параметров нормален (самые большие студенты останавливаются уже на 16–50-й эпохе).

### 3.2 Ёмкость (архитектура) — **хватает; больше сеть ≠ лучше**
| Датасет | A: [32,16,8] d0.2 (как сейчас) | B: [64,32,16] d0 | C: [128,64] d0 | D: A + 10× аугментация | E: C + аугментация |
|---|---|---|---|---|---|
| adult F1 / fid_hold / fid_train | 0.597 / 0.880 / 0.938 | 0.586 / 0.889 / 0.927 | 0.571 / 0.895 / 0.930 | 0.587 / 0.871 / 0.907 | 0.465 / 0.893 / 0.907 |
| covertype acc / fid_hold / fid_train | 0.681 / 0.866 / 0.818 | 0.677 / 0.857 / 0.880 | 0.675 / 0.862 / 0.890 | 0.660 / 0.862 / 0.820 | 0.668 / 0.880 / 0.882 |
| housing MAE / r_hold / r_train | 51 694 / 0.842 / 0.823 | 52 050 / 0.837 / 0.820 | 54 045 / 0.832 / 0.808 | 54 438 / 0.845 / 0.832 | 54 327 / 0.864 / 0.883 |
| wine MAE / r_hold / r_train | 0.505 / 0.881 / 0.919 | 0.490 / 0.892 / 0.950 | 0.497 / 0.886 / 0.936 | 0.506 / 0.884 / 0.908 | 0.485 / 0.894 / 0.947 |

(учитель LightGBM; аугментация — mixup пар train-точек + гауссов шум σ=0.05, размеченные учителем, MUNGE-подобный transfer set.)
- Увеличение сети в 2–5 раз поднимает **train**-fidelity (covertype 0.82→0.89, wine 0.92→0.95), но holdout-fidelity почти не меняется (±0.01–0.02), а метрика колеблется в пределах шума. Единственный намёк на нехватку ёмкости — covertype (7 классов, 54 признака): студент 2.5k параметров против 15.8k у MLP основного исследования, train-fidelity 0.82 < holdout 0.87 (dropout 0.2 мешает подгонке).
- Потолок fidelity ~0.86–0.94 при 400 точках — типичный: Stanton et al. 2021 показывают, что даже при достаточной ёмкости студент плохо совпадает с учителем, а главный рычаг — больше данных для переноса и оптимизация; Grinsztajn et al. 2022 — MLP смещены к гладким функциям, а деревья дают нерегулярные границы, которые MLP точно не повторит.

### 3.3 Цели (температура / мягкие метки) — **реализованы правильно; проблема в пороге учителя на adult**
- Мягкие цели используются везде (бинарная: p учителя; мультикласс: softmax(log p/T), KL·T²; регрессия: ŷ учителя). T=1 vs T=2 на covertype: 0.680 vs 0.681 acc, fidelity 0.865 vs 0.866 → температура не влияет (у деревьев вероятности и так не «пиковые», Hinton 2015 нужен T для «тёмного знания» в почти one-hot выходах нейросетей).
- **adult:** учитель хорошо ранжирует (ROC-AUC 0.840 против 0.848 у MLP-студента на метках) и откалиброван (среднее p=0.246 при доле позитивов 0.241), но F1 считается при пороге 0.5 → низкий recall → F1 0.53–0.56. MLP основного исследования учится с `pos_weight = neg/pos` и фактически сдвигает порог → F1 0.63. Студент копирует калиброванные вероятности учителя и наследует этот порог. Тот же студент на метках без pos_weight даёт 0.613, а при пороге по доле позитивов — 0.633. Значит, разница «дистилляция vs MLP» на adult — **артефакт порога и class weighting, а не качества дистилляции**. Это же касается сравнения деревьев с MLP в `models-*` (у деревьев F1 0.50–0.55 по той же причине).
- F1 при пороге 0.5 очень чувствителен: варианты студента с одинаковой fidelity ~0.88–0.89 дают F1 от 0.47 до 0.60 — для adult лучше дополнительно сохранять ROC-AUC / logloss.

### 3.4 Что не сохраняется / мелкие недочёты кода
- `study/protocol.py:226 distill_diagnostics` сохраняет только `teacher_metric` и `fidelity` (holdout). Нет эпохи остановки, train-fidelity, ROC-AUC, R² студент↔учитель (Pearson r для регрессии не чувствителен к сдвигу/масштабу).
- `models/torch_models.py:390-405` (`_build_student`): архитектура/lr/dropout студента захардкожены из `DEFAULT_PYTORCH_PARAMS['simple']`, датасетный конфиг MLP игнорируется — у разных датасетов студент одинаковый, и он не совпадает с MLP основного исследования (для «справедливого» сравнения дистилляция vs MLP на метках это смешивает два фактора).
- `models/torch_models.py` `DistilledModelWrapper.set_params` (стр. 621) не пересобирает студента и не обновляет `batch_size/num_classes/task_type/base_model`. `clone()` идёт через конструктор, поэтому в текущих путях это не мешает.
- Бинарная задача: `temperature` молча игнорируется (корректно, но не задокументировано).
- Сломанного ничего не найдено.

## 5. Рекомендации

**До полного прогона (дёшево, меняет интерпретацию):**
1. **Порог/веса классов на adult** (важно для выводов по F1 в distill / models-* / transfer). Вариант А (без изменения моделей): сохранять в `_baseline` и `distill_diagnostics` ещё ROC-AUC и logloss на holdout — threshold-free сравнение. Вариант Б (меняет результаты): веса классов у деревьев, как у MLP: LightGBM `scale_pos_weight = neg/pos` (≈3.2 на adult), XGBoost `scale_pos_weight` то же, CatBoost `auto_class_weights='Balanced'`, RF `class_weight='balanced'`. Рекомендую А обязательно; Б — если F1 остаётся главной метрикой сравнения моделей.
2. **Расширить `distill_diagnostics`** (`study/protocol.py`): эпоха остановки, train-fidelity, ROC-AUC (бинарная), R² студент↔учитель (регрессия). 0 секунд вычислений.

**Можно, но не обязательно:**
3. Студент = архитектура MLP из датасетного конфига (adult [64,32,16], covertype [128,64] с lr 2e-3, wine [16,8]) — ради честного сравнения «дистилляция vs MLP на метках», не ради качества (эксперимент 3.2 показывает ±шум). Для covertype dropout 0 → train-fidelity 0.82→0.89.
4. `distillation_epochs` 500 и patience 30 оставить; температуру T=2 оставить (не влияет).
5. Аугментация transfer set (mixup/MUNGE ×10) поднимает fidelity на 0–0.02 без выигрыша в метрике — **не нужна**.

**Для текста диплома:** дистилляция работает (fidelity 0.83–0.94, студент не хуже учителя в 5 из 8 пар, при 10 % шума иногда лучше — эффект сглаживания); то, что influence по студенту «не оживает», — не из-за плохой дистилляции, а из-за самого influence (см. `docs/PYDVL_AUDIT.md`, п. 1.6–1.9).
