# Схемы программного комплекса

Ниже — обобщённые диаграммы для включения в пояснительную записку: модульная структура, взаимодействие компонентов микросервиса и этапы обработки данных при запуске из главного модуля.

**Готовые файлы для вставки** (SVG и PNG) и исходники `.mmd` — в каталоге [`architecture_diagrams/`](architecture_diagrams/); кратко по форматам — в [`architecture_diagrams/README.md`](architecture_diagrams/README.md).

Дальше тот же текст в виде Mermaid в Markdown (удобно править и смотреть в GitHub / VS Code).

## 1. Модульная структура ПО

Главный модуль связывает настройки, подготовку данных, построение моделей и блок оценки влияния объектов обучения; результаты выводятся в виде отчётов и графиков.

```mermaid
flowchart TB
    subgraph entry [Точка входа]
        mainMod["Главный модуль\nзапуска экспериментов"]
    end

    subgraph core [Ядро]
        direction TB
        cfg["Параметры эксперимента\nи описание датасетов"]
        data["Загрузка данных,\nпредобработка признаков"]
        models["Модели\nдеревья / нейросети"]
        runner["Цикл экспериментов:\nобучение, влияние, удаление"]
        infl["Методы оценки влияния\nнаблюдений"]
    end

    subgraph out [Результат]
        viz["Визуализация\nи сводки"]
    end

    mainMod --> cfg
    mainMod --> data
    mainMod --> models
    mainMod --> runner
    mainMod --> viz
    data --> runner
    models --> runner
    runner --> infl
    infl --> models
```

## 2. Микросервис: взаимодействие компонентов

Пользователь работает через веб-интерфейс; запросы идут к программному интерфейсу приложения, где в фоне выполняется сценарий эксперимента; итоги сохраняются на диск.

```mermaid
flowchart LR
    subgraph client [Клиент]
        user["Пользователь"]
        ui["Веб-интерфейс"]
    end

    subgraph server [Сервер]
        api["REST API"]
        worker["Выполнение экспериментов\nпоэтапный сценарий"]
    end

    subgraph store [Хранение]
        files["Артефакты экспериментов\nвеса влияния, логи"]
    end

    user --> ui
    ui -->|"HTTP"| api
    api --> worker
    worker --> files
```

*Поэтапный сценарий на сервере:* загрузка данных → разбиение и выборка → предобработка → настройка модели → расчёт baseline, влияния и сценариев удаления → сохранение.

## 3. Этапы обработки данных при запуске главного модуля

Расширенный поток данных показывает точные этапы подготовки, обучения и оценки.

```mermaid
flowchart TD
    s1["Выбор датасета и загрузка конфигурации"]
    s2["Загрузка данных и первичный осмотр"]
    s3{"Задача классификации?"}
    s3a["Кодирование целевой переменной"]
    s4["Выделение holdout validation\n(отдельная, неизменная выборка)"]
    s5["Подвыборка для ускорения эксперимента"]
    s6["Разбиение на train/test для обучения и оценки"]
    s7["Обучение предобработчика на train"]
    s8["Преобразование train/test/validation"]
    s9["Сборка модели и параметров обучения"]
    s10["Обучение базовой модели и расчет метрик"]
    s11["Вычисление influence весов"]
    s12["Сценарии удаления данных и переобучение"]
    s13["Сохранение результатов, отчёты и визуализации"]

    s1 --> s2 --> s3
    s3 -->|да| s3a --> s4
    s3 -->|нет| s4
    s4 --> s5 --> s6 --> s7 --> s8 --> s9 --> s10 --> s11 --> s12 --> s13
```

### Внутренний цикл эксперимента

После подготовки данных выполняется последовательность: базовое обучение, создание конвейера, расчёт influence, проверка стратегий удаления и сравнение результатов.

```mermaid
flowchart LR
    b1["Обучение базовой модели\nна train"]
    b2["Создание конвейера: предобработка + модель"]
    b3["Вычисление influence весов\n(несколько методов)"]
    b4["Формирование стратегий удаления:\nнизкая/высокая/случайная/экстремальная"]
    b5["Переобучение и оценка после удаления"]
    b6["Сравнение метрик и сохранение результатов"]

    b1 --> b2 --> b3 --> b4 --> b5 --> b6
```
